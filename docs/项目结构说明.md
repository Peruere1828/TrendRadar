# TrendRadar 项目结构说明

这份文档用于快速理解当前项目每个目录和模块的职责。项目功能先全部保留，不删除原有能力；后续如果要重构代码，可以按本文最后的“推荐结构”逐步迁移。

## 一句话理解

TrendRadar 当前包含两条主要业务线：

1. **热点聚合主流程**：从多个热榜/RSS 源抓取新闻，按关键词或 AI 兴趣筛选，生成报告，并推送到邮件、飞书、钉钉等渠道。
2. **单网页监控模式**：给定一个网页链接、主题词和邮箱，定时发现新增文章，抓取正文，并通过邮件通知。这更接近当前业务需求。

现在文章正文抓取已经接入主流程：`cron/once` 模式生成 HTML 报告前，会按配置为命中的热榜/RSS 文章补充正文，邮件通知也会带上同一份正文内容。

## 核心代码：trendradar/

```text
trendradar/
  __main__.py             # 主入口：python -m trendradar
  context.py              # 应用上下文，集中持有配置、时间、存储、统计等能力
  single_watch.py         # 单网页监控：链接 + 主题词 + 邮箱
  webserver.py            # 容器内置 Web 服务，展示报告/兴趣配置等页面
```

### `__main__.py`

主流程入口。主要负责：

- 解析命令行参数。
- 加载 `config/config.yaml`。
- 启动热点抓取、关键词/AI 筛选、报告生成、通知推送。
- 在 HTML 生成前按配置抓取文章正文。
- 支持 `--doctor` 做配置体检。
- 支持 `--test-notification` 测试通知渠道。
- 支持 `--single-watch` 和 `--single-watch-loop` 进入单网页监控模式。

常用命令：

```bash
python -m trendradar
python -m trendradar --doctor
python -m trendradar --test-notification
python -m trendradar --single-watch
python -m trendradar --single-watch-loop
```

### `single_watch.py`

这是当前业务最相关的模块。它的职责是：

- 从环境变量或表单保存的配置读取：
  - `WATCH_URL`：要监控的网页链接。
  - `WATCH_KEYWORDS`：关注主题词。
  - `EMAIL_TO`：接收通知的邮箱。
  - `EMAIL_FROM` / `EMAIL_PASSWORD`：发信邮箱配置。
- 自动判断 URL 类型：
  - 人民网来源：使用 `PeopleCrawler` 的专门规则。
  - RSS/Atom：使用 RSS 抓取器。
  - 普通网页：解析页面中的文章链接。
- 记录已见过的文章，避免重复通知。
- 对新增文章做主题词匹配。
- 抓取文章正文。
- 生成邮件 HTML。
- 调用邮件发送器通知用户。

这条线未来可以继续扩展成“多用户网页监控服务”。

## 子模块职责

### `trendradar/core/`

基础业务逻辑层：

- `config.py`：配置加载、环境变量覆盖、多账号配置解析。
- `scheduler.py`：时间线调度，决定什么时候抓取、分析、推送。
- `frequency.py`：关键词统计和过滤。
- `data.py`：新闻数据整理。
- `loader.py`：配置/数据加载辅助。
- `analyzer.py`：统计结果转换，例如关键词视图转平台视图。

### `trendradar/crawler/`

数据抓取层：

- `fetcher.py`：多平台热榜抓取入口。
- `article_content.py`：文章正文抓取。
- `people_cn.py`：人民网专用抓取逻辑。
- `rss/fetcher.py`：RSS 抓取。
- `rss/parser.py`：RSS 解析。

### `trendradar/storage/`

数据存储层：

- `base.py`：存储数据结构和抽象接口。
- `local.py`：本地 SQLite/文件存储。
- `remote.py`：S3 兼容远程存储。
- `manager.py`：根据配置选择 local/remote。
- `schema.sql`、`rss_schema.sql`、`ai_filter_schema.sql`：数据库表结构。

### `trendradar/report/`

报告生成层：

- `generator.py`：组织报告数据。
- `formatter.py`：文本/Markdown 格式化。
- `html.py`：HTML 报告生成。
- `rss_html.py`：RSS 相关 HTML 展示。
- `helpers.py`：报告辅助函数。

### `trendradar/notification/`

通知发送层：

- `dispatcher.py`：统一调度所有通知渠道。
- `senders.py`：具体发送实现，包含邮件、飞书、钉钉、企业微信、Telegram、ntfy、Bark、Slack 等。
- `renderer.py`：通知内容渲染。
- `formatters.py`：不同渠道的格式处理。
- `splitter.py`：长消息拆分。
- `batch.py`：批量发送辅助。

### `trendradar/ai/`

AI 能力层：

- `client.py`：LiteLLM 客户端封装。
- `analyzer.py`：AI 新闻分析。
- `filter.py`：AI 兴趣筛选。
- `translator.py`：AI 翻译。
- `formatter.py`：AI 输出格式化。
- `prompt_loader.py`：提示词加载。

### `trendradar/utils/`

通用工具：

- `time.py`：时区、当前时间、日期判断。
- `url.py`：URL 处理。

## MCP 服务：mcp_server/

MCP 是给 AI 客户端使用的查询/分析服务，不是网页监控必须项。

```text
mcp_server/
  server.py               # MCP HTTP/stdio 服务入口
  tools/                  # 暴露给 AI 客户端的工具
  services/               # 数据、解析、缓存服务
  utils/                  # 参数校验、日期解析、错误类型
```

常见用途：

- 查询已抓取新闻。
- 按日期/关键词分析趋势。
- 读取文章。
- 管理配置。
- 触发数据同步。

如果只是做“网页更新后发邮件”，MCP 可以保留但不是主路径。

## 配置目录：config/

```text
config/
  config.yaml             # 主配置：数据源、通知、AI、存储、报告等
  timeline.yaml           # 定时策略：什么时候抓取、分析、推送
  frequency_words.txt     # 关键词分组
  ai_interests.txt        # AI 兴趣描述
  ai_analysis_prompt.txt  # AI 分析提示词
  ai_translation_prompt.txt
  ai_filter/              # AI 筛选相关提示词
  custom/                 # 自定义配置扩展目录
```

网页监控需求主要会用到：

- 邮件配置：`EMAIL_FROM`、`EMAIL_PASSWORD`、`EMAIL_TO`、SMTP 配置。
- 单网页监控环境变量：`WATCH_URL`、`WATCH_KEYWORDS`、`CHECK_INTERVAL`。
- 主流程正文抓取配置：`ARTICLE_CONTENT_ENABLED`、`ARTICLE_CONTENT_ONLY_NEW`、`ARTICLE_CONTENT_MAX_ARTICLES`。
- 输出目录：`output/single_watch/`。

## Docker 目录：docker/

```text
docker/
  Dockerfile                      # 主服务镜像
  Dockerfile.mcp                  # MCP 服务镜像
  docker-compose.yml              # 使用官方镜像运行
  docker-compose-build.yml        # 本地构建镜像运行
  docker-compose.single-watch.yml # 单网页监控模式
  docker-compose.server.yml       # 服务器端口版本：Web 7000，MCP 7001，容器名带 jjy 后缀避免冲突
  entrypoint.sh                   # 容器启动入口
  manage.py                       # 容器内管理命令，启动 Web 服务、查看状态等
  .env                            # Docker 环境变量，通常放密钥和端口
```

部署时优先看这几个：

```bash
cd docker
docker compose up -d
docker compose -f docker-compose-build.yml up -d
docker compose -f docker-compose.single-watch.yml up -d
```

## 输出目录：output/

运行产生的数据都在这里：

```text
output/
  news/                  # 热点/RSS 数据库
  html/                  # HTML 报告
  single_watch/          # 单网页监控状态、邮件 HTML
```

`output/` 应该挂载到宿主机，容器重启后数据不会丢。

## 当前需求对应的运行链路

```text
用户配置
  -> docker/.env 或 Web 表单保存的 config.json
  -> trendradar.single_watch.load_single_watch_config()
  -> SingleWatcher.fetch_articles()
  -> SingleWatcher._matches_keywords()
  -> ArticleContentFetcher.fetch()
  -> SingleWatcher._write_email_html()
  -> trendradar.notification.senders.send_to_email()
  -> output/single_watch/state.json 记录已通知文章
```

主流程正文抓取链路：

```text
python -m trendradar / RUN_MODE=cron
  -> NewsAnalyzer._run_analysis_pipeline()
  -> 关键词/AI 筛选得到 stats 和 rss_items
  -> NewsAnalyzer._enrich_report_items_with_article_content()
  -> ArticleContentFetcher.fetch()
  -> report.generator.prepare_report_data() 保留 article_content 字段
  -> report.html.render_html_content() 展示正文
  -> send_to_email() 发送同一份 HTML 报告
```

## 推荐的重构方向

现在先不移动代码文件，避免破坏原功能。后续如果要“重写项目结构”，建议逐步整理成下面这样：

```text
trendradar/
  app/
    cli.py                # 命令行入口，从 __main__.py 拆出来
    web.py                # Web 服务入口，从 webserver.py 拆出来
  config/
    loader.py             # 配置加载
    schema.py             # 配置结构定义和校验
  sources/
    hotlist/              # 热榜源
    rss/                  # RSS 源
    webpage/              # 普通网页监控源
    people_cn.py          # 人民网特殊源
  monitoring/
    single_watch.py       # 当前单网页监控
    jobs.py               # 多任务监控调度
    matching.py           # 主题词匹配
  content/
    fetcher.py            # 正文抓取
    extractor.py          # 正文解析
  notifications/
    email.py              # 邮件发送
    channels.py           # 其他渠道
  reports/
    html.py
    text.py
  storage/
    sqlite.py
    remote.py
  ai/
  mcp/
```

重构优先级建议：

1. 先把 `__main__.py` 拆小，因为它现在承担了太多职责。
2. 把 `single_watch.py` 中普通网页链接发现、RSS 自动发现等有价值能力迁入主流程的数据源层。
3. 把邮件通知从多渠道通知里单独抽成清晰的 `email.py`。
4. 再考虑多用户任务表、Web 表单、任务启停等功能。
